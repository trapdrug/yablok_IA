> Скопируй ВЕСЬ этот файл в ИИ на втором устройстве как единственный промт. ИИ должен работать автономно в цикле: код → запуск → проверка в браузере → исправление, пока не сдаст все acceptance-критерии.

## 0. Твоя роль и автономность

Ты — Senior Frontend Engineer + UX для бизнеса. У тебя ПОЛНЫЙ доступ к ПК: можешь ставить Node/npm, собирать Vite, открывать браузер, тестить кликами, чинить ошибки в цикле. Не спрашивай разрешения — действуй.

Цель: рабочее веб-приложение — «витрина» цифрового двойника «Сенсорики». Жюри за 3 минуты должно понять: что на складе, что в резервах/в пути, какие заказы в риске, что будет при задержке, зачем ИИ-аналитик + бонус производство. Вся логика цифр — на бэкенде Устройства 1, ты её только показываешь и вызываешь. Пока бэкенд не готов — работай на моке из `03 Простой пример.json`.

## 1. Входные данные и контракт (не выдумывай своё)

- Товары: `FG-AIR` (Air — температура+влажность), `FG-PLUS` (Air Plus — плюс CO2). Алиасы для поиска ИИ: Air/базовый/Аир; Air Plus/Air+/датчик с CO2/Аир Плюс.
- `scenario_now` = 2026-11-02T09:00+03:00. Дату ПК не показывать как «сейчас».
- Формулы (показывает бэкенд, ты дублируешь только для мока): свободно = on_hand − резерв; резерв = сумма reserved_qty активных; осталось = quantity − shipped_qty.
- Бэкенд Устройства 1 (порт 8000). Базовый URL — через `.env`: `VITE_API_URL=http://localhost:8000` (позже заменишь на LAN-IP бэкенда). Все запросы — по контракту ниже. Если бэкенд недоступен — автоматический fallback на локальный мок из `03 Простой пример.json` с пометкой «ДЕМО-МОК, API недоступен».

```
GET  /api/health
GET  /api/snapshot
GET  /api/orders?status=active
GET  /api/shipments
POST /api/orders {customer, sku, quantity, due_at}
POST /api/orders/{id}/reserve {qty}
POST /api/orders/{id}/ship {qty}
POST /api/shipments/{id}/receive
POST /api/scenarios/delay {shipment_id, new_expected_at}
GET  /api/production/status
POST /api/production/plan {finished_sku, batch_qty, start_from?}
POST /api/production/start {finished_sku, batch_qty}
POST /api/ai/ask {question, scenario?}
POST /api/admin/reset?fixture=simple|extended
```

## 2. Стек и структура (строго)

- Node 20+ (поставь сам: `winget install OpenJS.NodeJS.LTS`), Vite + React + TypeScript. Стили — чистый CSS или Tailwind (на твой выбор, но деловой светлый стиль, крупные KPI, бейджи рисков красным/зелёным).
- Порт 5173. Структура:
```
frontend/
  src/
    App.tsx           # роутинг вкладок
    api.ts            # fetch к VITE_API_URL + fallback mock.ts
    mock.ts           # загрузка 03 json + клиентский allocate (упрощённый по алгоритму из промта бэкенда)
    pages/Dashboard.tsx   # остатки/резервы/поставки + KPI
    pages/Orders.tsx      # активные заказы + нехватка + риск + действия
    pages/Shipments.tsx   # ожидаемые поставки + кнопка «Получить»
    pages/Scenario.tsx    # лаборатория задержки: выбор поставки + новая дата → diff до/после, threatened
    pages/Production.tsx  # допэтап: компоненты, BOM, план партии, Gantt-таймлайн
    components/AiChat.tsx # чат ИИ-аналитика (всегда видим, справа или отдельной вкладкой)

```
- Запуск одной командой: `npm i; npm run dev` → http://localhost:5173 открывается. Проверь сам в браузере.

## 3. Экраны (обязательный минимум для бизнеса)

1. **Шапка KPI (на всех экранах):** «Сенсорика • учебное время 02.11.2026 09:00 МСК», карточки: Air физически/свободно/резерв, Plus физически/свободно/резерв, активных заказов N, поставок в пути N, заказов в риске N (красным). Кнопки: «Сброс к простому примеру / к расширенному».
2. **Дашборд склада:** таблица SKU → on_hand / reserved / free + прогресс-бары; список expected-поставок (ID, SKU, qty, expected_at, просрочена?); подсказка «просрочена без received — исключена из прогноза».
3. **Заказы:** таблица активных: ID, клиент, SKU, qty, reserved, shipped, осталось, readiness (дата или «неизвестно — не хватает N»), бейдж «в срок / риск опоздания / нехватка». Фильтры по SKU и риску. Действия в строке: [+заказ] (модалка customer/sku/qty/due_at), [Резерв q] [Отгрузить q] (prompt с числом + обработка 400 с показом hint). Shipped/cancelled — серым внизу или скрыты toggle.
4. **Сценарная лаборатория (ключевой экран!):** селект поставки (только expected) + datetime новой даты + кнопка «Проверить задержку». Слева «Было», справа «Стало»: таблица готовности по заказам, красным — threatened (ID + причина: «не хватает X Air, ждали IN-AIR-01»). Дисклеймер: «расчёт на копии, склад не изменён». Пресет-кнопка: «IN-AIR-01 → 05.11 10:00» (эталон: ORD-003/005 в риске).
5. **Производство (допэтап):** остатки компонентов (таблица + красным нехватка CO2), BOM, incoming компонентов; форма «SKU партии + кол-во + старт» → результат: feasible да/нет, shortage, batch_ready_at или «вне горизонта 02–06.11», Gantt построчно (сборка/тест по времени, с учётом 09–17 и переносов на 09:00). Кнопка «Запустить партию» (списание, 409 если уже активна).
6. **ИИ-аналитик (чат):** поле вопроса + быстрые чипы: «Можно ли отдать 5 Plus новому клиенту?», «Почему ORD-003 нельзя отгрузить целиком?», «Что будет при задержке IN-AIR-01?», «Когда придёт IN-UNKNOWN?». Ответ + раскрывашка «на каких данных основан» (facts_used с бэкенда). Чат должен обновляться после каждого изменения склада/сценария (заново подтягивай snapshot). Алиасы товаров понимать (запрос «базовый датчик» = Air).

Дизайн: деловой, не «детский». Русский язык везде. Даты в МСК `ДД.ММ ЧЧ:ММ`. Пустые/ошибочные состояния — понятным текстом из `hint` API, а не пустым экраном.

## 4. Пошаговый план (по порядку)

1. `node -v`, `npm create vite@latest frontend -- --template react-ts`, `npm i`, запусти, открой http://localhost:5173 в браузере — заскриншоть.
2. `api.ts + mock.ts`: реализуй fetch-обёртку + мок-allocate по эталону (ORD-001 02.11 09:00, ORD-002 02.11 09:00, ORD-003 03.11 10:00, ORD-006 02.11 09:00, ORD-004 04.11 09:00, ORD-005 03.11 10:00). Дашборд KPI должен показать Air 18/6/12, Plus 8/5/3 без бэкенда.
3. Заказы + мутации (пока на моке с той же валидацией: запрет резерва сверх free, отгрузки без резерва, двойного получения). Затем переключи на реальный API когда Устройство 1 поднимет 8000 (смени VITE_API_URL, проверь CORS).
4. Сценарий задержки: два столбца до/после + threatened. Пресет IN-AIR-01→05.11.
5. Производство + Gantt (div-полоски по времени, без lib).
6. AiChat + facts_used + чипы вопросов.
7. Кнопки reset simple/extended, обработка просрочек (04.11 10:00 → IN-AIR-01/IN-PLUS-01 исключены), полировка CSS, README-ЗАПУСК.

## 5. Автономный цикл проверки (крути пока не зелёное)

После КАЖДОГО экрана: `npm run dev`, открой в браузере, кликни всё руками (создай заказ, зарезервируй, отгрузи, получи поставку, задержи поставку, спроси ИИ, спланируй партию). Открой DevTools → Console: красных ошибок быть не должно. Если бэкенд уже жив — те же клики должны менять реальные цифры (проверь через /docs бэкенда). Если ошибка — чини сразу. Финал: `npm run build` без ошибок.
